## Purpose

本能力讓獲授權使用者安全導入不同供應商版式的凍肉 PDF 報價，取得有原文證據、可人工覆核的結構化候選，同時確保自動識別結果不會直接成為正式報價或改寫實際入貨資料。

## ADDED Requirements

### Requirement: 授權使用者安全導入 PDF
系統 MUST 只允許擁有 `frozen.supplier_quotes.upload` 權限的已登入使用者導入 PDF，並 MUST 驗證檔案類型、大小及內容雜湊。原始文件 MUST 保存於 private storage，且同一 SHA-256 的重複上傳 MUST 返回既有文件及目前處理結果，而不得建立另一份文件。

#### Scenario: 成功導入有效 PDF
- **WHEN** 有上傳權限的使用者提交符合大小限制的文字型 PDF
- **THEN** 系統保存原始文件、檔名、MIME type、檔案大小、SHA-256、上傳者及上傳時間，並建立可追蹤的解析工作

#### Scenario: 拒絕無權或無效檔案
- **WHEN** 使用者沒有上傳權限，或提交非 PDF、空檔或超出大小限制的檔案
- **THEN** 系統拒絕導入且不得保存正式文件或候選報價行

#### Scenario: 重複文件
- **WHEN** 使用者再次提交 SHA-256 已存在的 PDF
- **THEN** 系統返回既有文件及其最新解析狀態，且不得建立重複文件

### Requirement: 通用分階段識別管線
系統 MUST 先以固定程式抽取 PDF 頁面、文字位置、閱讀順序及表格候選，再優先套用已啟用的供應商 profile。當 profile 不存在、版式不符或固定解析結果不足時，系統 MAY 呼叫結構化 AI 識別；供應商差異 MUST 以資料設定保存，不得要求每家供應商使用獨立程式分支。

#### Scenario: 已知供應商版式
- **WHEN** 文件可對應到已啟用且版式相符的 supplier profile
- **THEN** 系統使用該 profile 的欄位、頁首／頁尾及表格規則產生候選，並記錄使用的 profile 版本

#### Scenario: 未知或已變更版式
- **WHEN** 文件沒有可用 profile，或固定解析偵測到欄位／版式與 profile 不符
- **THEN** 系統將抽取後的必要文字及版面片段送入受控結構化識別，並把結果保留為待審核候選

#### Scenario: 多欄及混合表格
- **WHEN** PDF 同頁包含多欄、雙欄或不同頁使用不同欄位配置
- **THEN** 系統按頁面座標及欄位群組重建商品記錄，不得單純把整頁相同水平位置的不同欄商品合併為一行

### Requirement: 候選資料完整且可追溯
每筆識別候選 MUST 保存商品原始名稱、可選商品編號、中英文名稱、產地、規格、包裝、加工方式、原始價格文字、數值價格、貨幣、價格單位、供應狀態、條件、來源頁碼、來源原文、欄位級證據、解析器／profile／模型版本、匹配信心及匹配原因。無法可靠取得的欄位 MUST 為空，不得猜測。

#### Scenario: 有效商品候選
- **WHEN** 系統從 PDF 識別到一筆包含可驗證價格的商品記錄
- **THEN** 候選包含結構化欄位及可定位回 PDF 的頁碼和原文證據

#### Scenario: 缺少可選欄位
- **WHEN** PDF 沒有提供商品編號、產地或包裝
- **THEN** 系統把相應欄位保存為空，且不得根據其他商品或外部常識補值

#### Scenario: 條件文字
- **WHEN** PDF 包含包裝附加費、損耗比例、最低訂購量、運費或配送限制
- **THEN** 系統把條件與商品單價分開保存，並保留條件原文、適用範圍及確認狀態

### Requirement: 固定程式驗證自動識別結果
系統 MUST 以非 AI 程式驗證候選的數值、貨幣、單位、可用狀態、頁碼及原文證據。驗證失敗、證據缺失或欄位互相矛盾的候選 MUST 標記原因並要求人工處理，且 MUST NOT 自動確認。

#### Scenario: TBA 或暫缺
- **WHEN** 原文價格為 TBA、待定、暫缺、缺貨或空白
- **THEN** 系統保存相應供應狀態和原始文字，將數值價格保存為空，且不得轉成 0

#### Scenario: AI 回傳無原文支持的價格
- **WHEN** 結構化識別回傳的價格不能在指定頁碼及證據文字中驗證
- **THEN** 系統拒絕該數值、記錄驗證錯誤並把候選標記為待人工處理

#### Scenario: 單位不明或不可換算
- **WHEN** 價格單位缺失、模糊或與規格互相矛盾
- **THEN** 系統保留原始單位文字並要求人工選擇，且不得自行假定為每公斤價格

### Requirement: 供應商與日期必須由使用者確認
系統 MUST 分別展示從檔名、PDF 內文及 metadata 偵測到的供應商與日期候選。候選衝突或信心不足時 MUST 明確提示，且文件在使用者確認供應商、報價日期及生效日期前 MUST NOT 成為正式報價版本。

#### Scenario: 日期來源衝突
- **WHEN** 檔名、PDF 內文或 metadata 包含不同的日期候選
- **THEN** 審核畫面列出各候選及來源，要求使用者選擇正式日期，不得自動採用其中一個完成確認

#### Scenario: 供應商未能可靠識別
- **WHEN** 文件內容不能唯一對應到現有供應商
- **THEN** 系統將供應商保持未確認並要求使用者從現有供應商中選擇

### Requirement: 人工選擇及商品對應控制正式資料
系統 MUST 在審核畫面列出全部候選，但只有使用者選取、完成必要商品／variant／單位對應並提交的候選才可保存為 confirmed quote line。中低信心候選、規格差異及無法對應候選 MUST NOT 預設為已確認。

#### Scenario: 只確認部分候選
- **WHEN** 使用者只選取文件中的部分商品並完成對應後提交
- **THEN** 只有所選商品進入正式價格比較，未選候選保留於審核記錄但不得進入比較

#### Scenario: 同名不同規格
- **WHEN** 兩筆候選名稱相同但規格、包裝、加工方式、價格單位或其他定價條件不同
- **THEN** 系統把它們視為不同 variant，並阻止僅按商品名稱合併

#### Scenario: 低信心候選
- **WHEN** 商品匹配信心低於自動預選門檻或存在驗證警告
- **THEN** 審核畫面不預選該候選，並顯示信心、原因和警告供使用者處理

### Requirement: 已確認對應可安全復用
系統 MUST 可將使用者確認的供應商商品編號、名稱別名、規格 fingerprint 及欄位對應保存為具版本的 alias／supplier profile。後續文件 MAY 使用這些資料提高建議信心，但復用結果仍 MUST 遵守驗證與人工確認規則。

#### Scenario: 復用已確認商品別名
- **WHEN** 新文件出現與已確認 alias 及規格 fingerprint 相符的供應商商品
- **THEN** 系統建議對應的凍肉商品、標示別名證據並提高匹配信心，但不得直接提交正式報價

#### Scenario: Profile 變更
- **WHEN** 使用者確認新的欄位規則或版式變更
- **THEN** 系統建立或更新帶版本及審核人的 supplier profile，並保留該次解析實際使用的舊版本資訊

### Requirement: 解析失敗可診斷及重試
系統 MUST 提供可觀察的處理狀態、非敏感錯誤摘要及重試能力。文字抽取為空的文件 MUST 進入 `ocr_required`；其他可恢復失敗 MUST 進入 `parse_failed`。重試 MUST 保持冪等，且不得覆寫已確認 quote line。

#### Scenario: 掃描型 PDF
- **WHEN** PDF 有頁面但固定文字抽取結果為空或不足以識別內容
- **THEN** 系統保存文件並標記為 `ocr_required`，不產生虛構候選，且讓使用者知道本期需另行處理 OCR

#### Scenario: 解析服務失敗後重試
- **WHEN** 文件因暫時性解析或 AI 服務錯誤進入 `parse_failed` 後由獲授權使用者重試
- **THEN** 系統建立新的解析嘗試並更新未確認候選，保留歷次版本與錯誤摘要

#### Scenario: 重試已確認文件
- **WHEN** 使用者要求以新解析器重試已存在 confirmed quote line 的文件
- **THEN** 系統不得覆寫或刪除已確認 line，只能產生隔離的新候選供另行比較與確認

### Requirement: AI 及導入流程不得改寫既有業務資料
AI 與 PDF 導入流程 MUST NOT 直接新增或修改 `raw_meat_items`、`raw_meat_stock_movements`、既有已確認 supplier quote line 或其他實際入貨／價格版本。送往 AI provider 的內容 MUST 限於識別所需的抽取片段，且 API secret MUST 只存在於 server-side runtime。

#### Scenario: AI 建議新商品
- **WHEN** AI 無法把候選對應到現有凍肉商品並建議建立新商品
- **THEN** 系統只把候選標記為「新商品待建立」，不得自動新增 `raw_meat_items`

#### Scenario: 解析完成
- **WHEN** PDF 解析及候選識別成功完成
- **THEN** 系統只保存文件、解析工作及未確認候選，不得改寫任何實際入貨記錄或正式報價歷史
