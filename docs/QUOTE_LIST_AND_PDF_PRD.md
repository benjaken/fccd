# 報價列表與可編輯 PDF PRD

| 項目 | 內容 |
| --- | --- |
| 文件狀態 | 草案，供確認後開發 |
| 範圍 | Catering 報價列表、報價 PDF 編輯／輸出、關聯文件及複製流程 |
| 參考 | 使用者提供截圖 1–8；目前 `QuotesListPage`、報價條款／付款方式 snapshot 資料結構 |

## 1. 目標

讓使用者能從報價列表快速找出報價、辨識跟進狀態，並直接產生一份可在輸出前編輯條款、付款方式與客戶簽署區的正式報價 PDF。

本 PRD 的「可編輯 PDF」是指：在系統內使用報價資料建立可編輯的文件預覽，確認後輸出 PDF／開啟瀏覽器列印預覽；不是讓使用者直接修改已生成 PDF 二進位檔案。

## 2. 範圍

### 2.1 包含

- 報價列表：搜尋、單日／多日建立日期篩選、顯示全部切換、品牌篩選、建立日期與報價單號排序、欄位及操作。
- 單筆報價操作：PDF、編輯、上傳關聯文件、複製。
- 報價 PDF 文件編輯：選取／移除／新增條款及細則、選取／移除／新增付款方式、顯示客戶簽署區、確認後輸出／列印 PDF。

### 2.2 不包含

- 更改報價計價、轉訂單或 CRM 跟進本身的業務流程。
- 條款及付款方式全域設定頁的新增、編輯、停用與排序；本期僅從既有可用模板中搜尋及加入單筆報價。
- 電子簽署、客戶在線簽名流程、寄送電郵、正式電子發票。
- 修改已輸出的 PDF；重新開啟報價後以保存的文件設定重新生成。

## 3. 報價列表

### 3.1 顯示範圍

1. 列表預設只顯示有效跟進中的報價，**不顯示**報價狀態為 `Done Deal` 或 `Case Closed` 的報價。
2. 工具列提供「顯示全部」核取方塊：
   - 未剔選：套用上述預設，隱藏 `Done Deal` 與 `Case Closed`。
   - 已剔選：顯示所有報價，包括 `Done Deal` 與 `Case Closed`。
3. 此顯示全部條件須與搜尋、日期篩選、品牌篩選及各既有報價預設列表共同生效。
4. 系統應顯示符合目前篩選條件的結果總數。

### 3.2 搜尋與篩選

1. 文字搜尋可搜尋報價單號、客戶／公司名稱、電話、電郵及送貨地址。
2. 新增「建立日期」範圍控制（**以報價建立日期為唯一判斷依據，不使用送貨日期**）：
   - 範圍模式提供「單日」與「多日」；預設為「多日」，以符合截圖 1。
   - 單日模式使用單一 Datepicker，只顯示香港時區該建立日期的報價。
   - 多日模式使用 Datepicker Range，顯示開始日至結束日（含首尾兩日）建立的報價。
   - 結束日期不得早於開始日期；多日模式尚未選完整範圍時不套用不完整篩選。
   - 未選日期時，不套用建立日期篩選。
3. 品牌可多選篩選；選取多個品牌時採 **OR** 邏輯，未選時顯示所有品牌。品牌定義暫以訂單所屬渠道（channel）為候選資料來源，待確認。
4. 變更搜尋、顯示全部、日期或品牌篩選時，回到第一頁。條件需保留於網址查詢參數，讓重新整理與分享連結後仍可還原。

### 3.3 表格欄位與排序

表頭、欄位順序及每列資訊依截圖 1 定義如下：

| 順序 | 欄位 | 顯示規則 |
| --- | --- | --- |
| 1 | 品牌 | 報價所屬品牌／渠道名稱；欄首提供品牌篩選。 |
| 2 | 建立日期 | 報價建立日期（香港時區）；欄首可切換升冪／降冪排序。 |
| 3 | 報價單號 | 報價單號；可點擊進入報價詳情／編輯頁；欄首可切換升冪／降冪排序。 |
| 4 | 客戶 | 依序顯示客戶／公司名稱、電話、送貨地址、送貨日期、送貨時間、出車時間、數量，以及 Asana Link（有資料時）。Asana Link 必須連結至該報價已關聯的 Asana 工作項目，於新分頁開啟；沒有關聯時顯示 `—`，不可產生空白連結。缺少其他資料顯示 `—`。 |
| 5 | 報價單描述 | 顯示可編輯的報價描述；空白時顯示提示文字。 |
| 6 | 總額 | 依報價幣別顯示總額；沒有財務查看權限時隱藏欄位。 |
| 7 | 生成訂單 | 顯示報價是否已轉成訂單及其結果／狀態（例如「未完成送出」）。具備權限的使用者可由此進入既有轉訂單流程。 |
| 8 | 報價狀態 | 依截圖按順序顯示「成功機率／Status」、「報價渠道／Sales from」、「溝通渠道／Channels」三個下拉選擇欄位；具權限的使用者可在列表中逐筆選擇並即時保存，無權限者只讀顯示。 |
| 9 | 操作 | PDF、編輯、關聯文件、複製。 |

排序規則：首次進入沿用目前預設排序；點擊「建立日期」或「報價單號」後，於升冪／降冪間切換。當兩筆資料排序值相同時，以另一個可排序欄位及報價 ID 做穩定次排序。

### 3.4 Asana 連結與列表內狀態更新

1. 報價可保存一個 Asana 工作項目連結（URL）。在列表客戶欄的 `Asana Link` 點擊後，以新分頁開啟該連結，並使用 `noopener` 安全設定。
2. Asana 連結只負責跳轉至既有 Asana 工作項目；本期不包含直接在列表建立 Asana 工作、讀取任務狀態或雙向同步。
3. 每筆報價的「成功機率／Status」、「報價渠道／Sales from」、「溝通渠道／Channels」均使用獨立下拉選單，第一期選項固定如下，不可混用：

   | 欄位 | 下拉選項 |
   | --- | --- |
   | 成功機率／Status | `Low Chance`、`High Chance`、`Done Deal`、`Case Closed` |
   | 報價渠道／Sales from | `Online Enquiry`、`Referal`、`Email` |
   | 溝通渠道／Channels | `WATI`、`Email`、`Phone` |

   三欄均允許未選擇值；未選時顯示其欄位 placeholder（`Status`、`Sales from`、`Channels`）。
4. 使用者選定一個值後，系統立即保存該單一欄位，並在儲存中顯示 loading／停用該選單，避免重複提交。
5. 儲存成功後保留新選值；失敗時回復原值並顯示可理解的錯誤訊息，且不得影響同列其他欄位或其他報價。
6. 成功機率選擇 `Done Deal` 或 `Case Closed` 後，若「顯示全部」沒有勾選，該筆報價會在儲存成功後從目前列表移除；勾選「顯示全部」時，該筆仍保留並顯示新狀態。

## 4. 單筆報價操作

| 操作 | 行為 | 規則／結果 |
| --- | --- | --- |
| PDF | 開啟第 5 節的可編輯報價 PDF 預覽 | 可編輯條款及細則、付款方式與客戶簽署顯示；確認後輸出／列印。 |
| 編輯 | 開啟報價編輯頁 | 載入現有報價內容；需報價編輯權限。 |
| 上傳關聯文件 | 開啟附件上傳與管理面板 | 上傳的檔案與該報價 ID 關聯；可列出、下載／預覽及刪除具權限的檔案。 |
| 複製 | 建立草稿報價後進入編輯頁 | 複製客戶、送貨資料、品項、描述、價格、折扣、條款與付款方式；不得複製報價單號、原始轉訂單結果、溝通／跟進記錄、附件、列印紀錄、建立／更新者與時間戳。儲存後按正常規則產生新報價單號。 |

附件規則：接受的檔案類型、單檔／總容量上限、惡意檔案掃描與保留期限須沿用或在開發前確認系統檔案政策。檔案必須存於私有儲存空間，以簽名網址提供下載／預覽，不得公開暴露客戶資料。

## 5. 可編輯報價 PDF

### 5.1 開啟與主預覽

1. 點擊 PDF 後，開啟報價文件預覽頁（不可直接下載未確認版本）。
2. 預覽至少包含截圖 2、7、8 所示內容：
   - 品牌 logo、公司資料、證書／品牌圖示（如該品牌已設定）。
   - 報價標題與報價單號。
   - 客戶名稱、公司名稱、聯絡資料、送貨地址、報價日期、送貨日期及送餐時段。
   - 報價項目、單價、份數、總數、小計、運費與總額。
   - 條款及細則區塊。
   - 付款方式區塊。
   - 可選的客戶簽署區，以及發出者、公司蓋印／簽署區、頁碼與頁尾公司聯絡資料。
3. 內容超過一頁時，必須正常分頁，表格表頭、頁碼與頁尾不得重疊；列印預覽顯示實際頁數。
4. 如果資料缺漏，應顯示 `—` 或略過空白區塊，不能因空值生成失敗。

### 5.2 條款及細則

1. 條款區塊旁提供「+」入口，開啟「條款及細則」選取彈窗（截圖 3）。
2. 彈窗內提供 `Search T&C` 搜尋框，輸入文字後即篩選既有條款模板（截圖 4）；搜尋範圍為模板內容。
3. 使用者選擇一項模板後點擊 `Add`，加入目前報價文件的條款列表；可重複加入多項。
4. 已加入的條款以原順序編號顯示；每項有移除按鈕。點擊確定後套用並回到 PDF 預覽。
5. PDF 預覽中的條款內容可新增一段自由輸入文字（如截圖 6 的 `Type here...`）；自由文字只屬於此報價，不會回寫或建立全域條款模板。
6. PDF 預覽中的條款順序可於本期以加入順序為準；拖拉排序不在本期範圍。

### 5.3 付款方式

1. 付款方式區塊旁提供「+」入口，開啟「付款方式」選取彈窗（截圖 5）。
2. 彈窗內提供 `Search payment method` 搜尋框，以付款方式內容篩選既有付款方式模板。
3. 使用者選擇付款方式並點擊 `Add` 後，加入目前報價文件；可加入多項並可移除。
4. 已加入付款方式在 PDF 中依加入順序編號顯示（截圖 6）。本期不提供自由輸入付款方式，避免非授權的付款資料出現在正式報價；若需自訂，另行確認權限及資料管理規則。

### 5.4 客戶簽署與輸出

1. 預覽提供「顯示客戶簽署」核取方塊；未勾選時不顯示客戶簽署區，勾選時顯示截圖 6 所示「請仔細閱讀以上內容並簽署確認」、客戶名稱、公司蓋印及簽署、負責人姓名、簽署日期欄位。
2. 此功能只顯示簽署欄位供實體列印／手寫，**不代表電子簽署已完成**。
3. 使用者點擊「確定」後，先保存目前報價的條款、付款方式及客戶簽署顯示設定，再開啟瀏覽器 PDF／列印預覽（截圖 7、8）。
4. 列印預覽提供目標印表機、頁面、份數、彩色等由瀏覽器／作業系統控制的設定，並可列印或取消。取消列印不可回滾已保存的文件設定。
5. 同一報價之後再次開啟 PDF 時，必須還原最近保存的條款、付款方式、自由條款文字及客戶簽署顯示設定。

## 6. 資料、權限與稽核

### 6.1 資料

| 資料 | 來源／處理 |
| --- | --- |
| 報價主資料、客戶、金額、送貨資料、品項 | `orders`（`document_type = quote`）及 `order_lines` 的 snapshot。 |
| 條款、付款方式 | 現有 `quote_terms_templates`、`quote_payment_templates` 作為可搜尋模板；每份報價使用 `order_terms_snapshots`、`order_payment_method_snapshots` 保存當時內容。 |
| 關聯文件 | `attachments` 私有儲存及以報價 ID 作 owner 關聯。 |
| 品牌 | 候選來源為 `channels`；需確認是否等同使用者所稱品牌。 |
| Asana 連結 | 報價的 Asana 工作項目 URL；需確認既有欄位或新增 snapshot／metadata 欄位。 |
| 成功機率、報價渠道、溝通渠道 | 三組獨立的選項主檔及報價 snapshot／關聯欄位；列表更新時只更新被選擇的單一欄位。 |
| 客戶簽署設定 | 需保存於報價文件設定／snapshot；若現有表沒有對應欄位，須新增。 |
| PDF 產出紀錄 | 需保存最後產出時間、操作者及版本／內容雜湊；實體列印成功與否通常無法由瀏覽器可靠回傳，紀錄應標示為「已開啟列印預覽」。 |

### 6.2 權限

| 能力 | 最低權限 |
| --- | --- |
| 查看報價列表及報價內容 | 報價查看權限。 |
| 查看總額 | 財務查看權限。 |
| 編輯報價、更新描述／狀態、複製 | 報價編輯／建立權限。 |
| 加入／移除 PDF 條款、付款方式、設定客戶簽署 | 報價文件編輯權限。 |
| 產出／列印 PDF | 報價文件查看／輸出權限。 |
| 上傳、下載、刪除關聯文件 | 對應的報價附件權限；刪除須為獨立權限。 |

至少需稽核：報價狀態變更、建立／複製報價、附件上傳／下載／刪除、PDF 設定儲存、開啟 PDF／列印預覽。紀錄包含操作者、時間、報價 ID、動作與結果。

## 7. 非功能需求與驗收標準

1. 未勾選「顯示全部」時，列表不顯示 `Done Deal`、`Case Closed`；勾選後兩者出現，且仍受其他條件過濾。
2. 建立日期可切換單日 Datepicker 及多日 Datepicker Range，採香港時區與含首尾日期的正確結果；可與品牌及文字搜尋共同套用。
3. 表格按第 3.3 節顯示欄位；品牌可篩選，建立日期及報價單號可正確升冪／降冪排序。
4. 有 Asana 關聯的報價可透過 Asana Link 在新分頁開啟正確工作項目；無關聯時不顯示可點擊連結。
5. 具權限的使用者可在列表逐筆選擇成功機率、報價渠道、溝通渠道；每個選擇獨立保存，失敗可還原，且選為 Done Deal／Case Closed 時遵守「顯示全部」規則。
6. 每筆報價按權限提供 PDF、編輯、上傳關聯文件及複製操作。
7. PDF 預覽能加入、搜尋及移除條款；自訂條款文字會保存並再次開啟時還原。
8. PDF 預覽能加入、搜尋及移除付款方式，且不會修改全域付款方式模板。
9. 客戶簽署可切換顯示；確認後產生含正確報價資料、條款、付款方式與簽署區的多頁 PDF／列印預覽，頁碼正確且不重疊。
10. 複製產生獨立草稿報價，不複製單號、附件、跟進記錄或原始轉訂單結果。
11. 關聯文件只有具權限的使用者可存取，並以私有檔案及短效簽名網址處理。
12. 無財務查看權限者不可看到列表總額或 PDF 中的金額資料；若業務需要客戶報價 PDF 仍顯示金額，必須另行定義「可輸出客戶報價」權限，不可沿用財務查看權限而造成角色混亂。

## 8. 開發前待確認事項

1. 品牌是否直接使用渠道（channel）名稱？
2. 「生成訂單」欄位的所有狀態、按鈕行為及 Done Deal／Case Closed 與轉單之間的關係是甚麼？
3. 報價 PDF 的品牌版型、logo、公司抬頭、認證圖示、印章、頁尾與語言是否隨品牌改變？由誰維護？
4. 條款與付款方式在選取後是否允許單筆報價覆寫原文？本 PRD 允許自訂條款文字、不允許覆寫付款方式，請確認。
5. 是否需將輸出的 PDF 檔案持久保存為附件／版本，還是只需保存生成設定與列印預覽稽核？
6. 附件允許的檔案類型、大小上限、是否支援多檔、是否需要下載／刪除／版本紀錄？
7. Asana 工作項目連結由使用者在報價編輯頁手動填寫，還是需串接 Asana API 自動建立／選取？本 PRD 本期預設只開啟已保存的連結。
