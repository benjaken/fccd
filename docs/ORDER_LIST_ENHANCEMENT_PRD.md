# 訂單列表欄位、篩選與操作 PRD

| 項目 | 內容 |
| --- | --- |
| 文件狀態 | 草案，供確認後開發 |
| 範圍 | Catering 訂單模組的「所有列表」及所有其他訂單預設列表 |
| 參考 | 使用者提供截圖 1–6；目前 `OrdersListPage` 的共用列表實作 |

## 1. 背景與目標

現有訂單列表僅提供訂單號碼、客戶名稱、送貨資料、狀態及部分財務資料，使用者需要在同一頁快速掌握完整派送與待辦情況，並直接完成常用訂單操作。

本需求的目標是：

1. 統一所有訂單列表的欄位，使排程、客戶、標籤、數量與金額可一眼查看。
2. 在「所有列表」提供品牌、地區、節日及 Tag 篩選，以及付款／工場傳送的待辦提示。
3. 在每筆訂單提供編輯、溝通、取消、送貨單、打印、發票、複製等操作。

## 2. 範圍

### 2.1 包含

- 「所有列表」（`/orders`）及所有既有訂單預設列表共用新的表格結構。
- 節日與 Tag 篩選。
- 每筆訂單的操作選單／按鈕。
- 取消訂單確認、複製訂單進入編輯頁。
- 開啟或生成送貨單、收據／打印版、發票版。

### 2.2 不包含

- 更改訂單建立、計價、付款或派送流程本身。
- 重新設計送貨單、收據、發票的品牌版型；本期以截圖 4–6 所示既有內容與版型為基準。
- 新增節日設定後台；本期只消費已確認的節日資料來源。
- 批量操作、匯出、欄位自訂、拖拉排序。

## 3. 名詞與適用列表

| 名詞 | 定義 |
| --- | --- |
| 所有列表 | 預設值 `all`，路徑 `/orders`。本頁顯示「代辦」欄。 |
| 其他訂單列表 | 待入單、未付款、已送貨未付款、月結、拆單、廚房備註、改期、Shopify 待處理、未傳送到工場等既有預設列表。這些頁面不顯示「代辦」欄，其餘欄位與操作一致。 |
| 節日 | 與訂單送貨日期相符的營運節日標記；不是餐廳員工請假。 |
| Tag | 已套用至訂單的訂單狀態／標籤，可同時有多個。 |
| 未完成付款 | 訂單未結餘額大於 0。 |
| 未傳送到工場 | 訂單尚未標記為已傳送至工場。 |

## 4. 功能需求

### 4.1 列表欄位

所有訂單列表以以下欄位順序顯示。可沿用現有日期、金額格式及財務權限規則。

| 順序 | 欄位 | 顯示內容／規則 |
| --- | --- | --- |
| 1 | 選取 | 保留現有或未來批量操作所需的核取方塊；本期不實作批量操作。 |
| 2 | 品牌 | 訂單所屬品牌／渠道名稱。無資料時顯示 `—`。 |
| 3 | 訂單號碼 | 訂單號碼；可點擊進入訂單詳情或編輯流程。 |
| 4 | 客戶 | 依序顯示客戶／公司名稱、電話、送貨地址；缺失資料逐項顯示 `—`。 |
| 5 | 節日篩選 | 顯示該送貨日期所匹配的節日名稱；沒有節日則顯示 `—`。欄首提供節日篩選入口。 |
| 6 | 地區 | 送貨地址所屬地區；無資料時顯示 `—`。 |
| 7 | 送貨日期 | 送貨日期，支援排序。 |
| 8 | 出車 & 送餐時間 | 第一行「出車時間」，第二行「送貨時間」；送貨時間可為時間範圍。 |
| 9 | Tag | 顯示所有已套用 Tag，以彩色標籤呈現；欄首顯示已選數量並可篩選。 |
| 10 | 數量 | 所有未取消訂單項目的數量總和；支援小數量時依既有數字格式顯示。 |
| 11 | 總額 | 訂單總額，依訂單幣別格式化；沒有財務查看權限時隱藏欄位及內容。 |
| 12 | 代辦 | **只在「所有列表」顯示。** 以個別狀態標籤顯示系統自動代辦「未完成付款」及／或「未傳送到工場」，以及使用者手動加入的更多狀態。兩項皆不成立且沒有手動狀態時顯示 `—`。沒有財務查看權限的使用者不得看到「未完成付款」標籤。 |
| 13 | 操作 | 每筆訂單提供第 4.3 節的操作入口。 |

說明：其他預設訂單列表只移除「代辦」欄；不可因為預設列表而移除品牌、客戶詳情、節日、地區、時間、Tag、數量、總額或操作欄。若使用者沒有財務查看權限，仍應在所有列表及其他列表隱藏「總額」和與付款有關的待辦內容。

### 4.1.1 代辦：選擇更多狀態

1. 「所有列表」的每筆訂單，在代辦欄提供「選擇更多狀態」入口；可點擊代辦欄的新增按鈕或狀態區域開啟彈窗。
2. 彈窗標題為「選擇更多狀態」，版面依截圖顯示可點擊的膠囊狀態按鈕。第一期預設選項為：`改期未定`、`WP`、`BW`、`FP`、`KLOOK`、`Alipay`、`已拆單`、`月結`。
3. 同一訂單可同時選擇多個更多狀態；再次點擊已選狀態即移除。已選與未選狀態必須有清楚視覺區分，並在關閉彈窗後立即更新該列。
4. 更多狀態屬於使用者可維護的訂單 Tag／代辦標籤，不可覆寫或移除系統自動計算的「未完成付款」及「未傳送到工場」。
5. 使用者只可新增／移除更多狀態，不可在此彈窗新增、改名或刪除全域狀態選項；全域選項維護方式列為後續需求。
6. 更多狀態必須被保存；重新整理、切換分頁或重新登入後仍須正確顯示。Tag 篩選應可篩選這些更多狀態。
7. 沒有訂單編輯／代辦更新權限的使用者可閱讀代辦標籤，但不可開啟修改彈窗。

### 4.2 篩選、搜尋、排序與分頁

1. 保留現有訂單狀態篩選、文字搜尋、分頁及各預設列表的既有篩選條件。
2. 文字搜尋須同時支援訂單號碼、客戶／公司名稱、客戶電話、送貨地址搜尋。
3. 新增「搜尋送貨日期」範圍控制，位於列表搜尋列，版面及操作參考截圖：
   - 範圍模式下拉選單提供「單日」及「日期範圍」，預設為「單日」。
   - 選擇「單日」時，顯示單一日期 Datepicker，使用者選取一個送貨日期後只顯示當日送貨訂單。
   - 選擇「日期範圍」時，顯示 Datepicker Range，使用者選取開始及結束日期後，顯示含首尾兩日之間的所有送貨訂單。
   - 「未來30日送貨」快捷按鈕：以香港時區當日為第 1 日，篩選今天至 29 日後（共 30 個曆日）送貨的訂單。
   - 「今日送貨」快捷按鈕：篩選香港時區當日送貨的訂單。
   - 點擊快捷按鈕後，範圍控制應同步顯示實際生效的日期／日期範圍；若用戶手動選擇日期，原先的快捷選取狀態即取消。
   - 未選送貨日期時，不套用送貨日期篩選；日期篩選以訂單送貨日期判斷，不以建立日期、工場日期或出車時間判斷。
   - 選擇日期範圍時，結束日期不可早於開始日期；尚未選完整範圍前，不送出半成品篩選。
4. 新增「品牌篩選」：
   - 下拉多選訂單所屬品牌；未選擇時顯示所有品牌。
   - 選取多個品牌時採 **OR** 邏輯，即符合任一已選品牌的訂單均顯示。
5. 新增「地區篩選」：
   - 下拉多選送貨地區；未選擇時顯示所有地區。
   - 選取多個地區時採 **OR** 邏輯，即符合任一已選地區的訂單均顯示。
6. 新增「節日篩選」：
   - 預設為「全部節日狀態」。
   - 可選「只顯示節日訂單」、「只顯示非節日訂單」及指定節日名稱。
   - 以訂單送貨日期與節日日期匹配；不以建立日期、工場日期或出車時間判定。
   - 篩選套用後，列表總數與分頁需同步重新計算。
7. 新增「Tag 篩選」：
   - 多選 Tag；選取多個 Tag 時採 **AND** 邏輯，即訂單必須同時擁有所有已選 Tag。
   - 顯示已選 Tag 數量；清除篩選後回到全部 Tag。
8. 送貨日期欄支援升冪／降冪排序；首次進入時沿用現行列表預設排序，使用者點擊欄首後在升冪與降冪間切換。
9. 篩選、搜尋或排序改變後一律回到第一頁；篩選條件應保留於網址查詢參數，讓重新整理與分享連結後狀態一致。

### 4.3 單筆訂單操作

操作欄建議使用「⋯」選單，以避免表格在小螢幕過寬；常用操作可依設計稿改為圖示按鈕。每項操作都必須以訂單權限控制可見性與可執行性。

| 操作 | 行為 | 規則／結果 |
| --- | --- | --- |
| 編輯 | 開啟該訂單編輯頁 | 載入原訂單資料。沒有編輯權限則不顯示或顯示為停用。 |
| 溝通 | 開啟「留言」彈窗 | 依截圖 3 顯示訂單投訴、訂單讚好、客戶備註三個分頁及留言時間線；可輸入及送出新留言。 |
| 取消訂單 | 開啟取消確認彈窗 | **只在送貨狀態為「待接單」時顯示及可執行。** 依截圖 2，使用者必須輸入完全相符、不分大小寫的 `void` 才可確認。確認後訂單標記為取消／void，不從資料庫硬刪除；列表、金額、待辦及可用操作即時更新。 |
| 送貨單 | 開啟送貨單預覽 | 使用截圖 4 的送貨單內容：品牌標識、客戶與送貨地址、訂單／送貨日期／送貨時間／送貨日子、訂單內容及頁碼。預覽可打印。 |
| 打印 | 開啟收據／打印預覽 | 使用截圖 5 的 RECEIPT 內容，包含客戶、聯絡人、送貨資料、項目、單價、數量、小計／總額、付款資料與簽章區；預覽可打印。 |
| 發票 | 開啟發票預覽 | 使用截圖 6 的 INVOICE 內容，包含收據資料、條款及細則、付款方式、客戶簽署及公司簽署區；支援在預覽頁打印。 |
| 複製 | 複製該訂單後進入新增訂單編輯頁 | 建立一份新的草稿訂單，不覆寫原訂單。複製客戶、送貨資料、項目、備註、Tag、價格及折扣；不得複製訂單號碼、付款紀錄、發票／收據號碼、派送／工場處理狀態、留言、附件、列印紀錄、取消狀態與建立／更新者時間戳。新草稿的送貨日期與時間保留原值但可編輯，儲存後依正常規則產生新訂單號碼。 |

### 4.4 取消、列印與複製的例外處理

1. 已取消訂單不可以再次取消；送貨狀態不是「待接單」的訂單亦不可取消。兩種情況均不顯示取消操作；可視權限保留檢視、溝通及單據預覽。
2. 取消動作失敗時不可關閉彈窗，需顯示錯誤，並保留已輸入的確認字串。
3. 若訂單沒有訂單項目、客戶或送貨資料，單據仍須可開啟，缺少欄位顯示 `—`，不可產生空白頁或前端錯誤。
4. 複製失敗不得產生部分草稿；使用者應留在原列表並看到可理解的錯誤訊息。
5. 所有列印預覽應在新頁面或受控預覽視窗開啟，避免瀏覽器彈出視窗封鎖影響操作；列印完成／取消不改變訂單狀態。
6. 更多狀態儲存失敗時，彈窗不得顯示為成功；需顯示錯誤並保留使用者剛剛選取的狀態，以便重試。

## 5. 資料與技術需求

### 5.1 現有資料可直接使用

- 客戶名稱、電話與送貨地址：`orders` 的 snapshot 欄位。
- 送貨日期、出車時間、送貨時間、總額、未結餘額、是否已傳送工場：`orders`。
- Tag：訂單狀態／Tag 關聯資料。
- 更多狀態：沿用訂單 Tag／狀態關聯資料，並識別為「可手動管理的代辦狀態」；不得與系統自動代辦混為同一個可移除來源。
- 數量：加總同一訂單下未取消的 `order_lines.quantity`。
- 留言：`order_timeline_entries`。

### 5.2 須補足或確認的資料

| 項目 | 現況／需求 |
| --- | --- |
| 品牌 | 需確認品牌是否等同現有 `channel`。若是，列表查詢須帶出渠道名稱；若否，須指定品牌主檔及關聯欄位。 |
| 地區 | 目前訂單主表保存完整送貨地址；需確認地區是既有地址欄位／主檔、地址解析結果，或需新增可維護的地區 snapshot。 |
| 節日 | 現有 `restaurant_holidays` 為員工假期，不能直接作為本需求節日。需確認營運節日資料表、日期欄位及適用品牌／地區規則；若尚未存在，須先建立節日主檔。 |
| 送貨時間 | 目前訂單主表已有出車時間；送貨時間欄位與來源需在資料模型確認，並定義單一時間／時間範圍格式。 |
| 單據編號與模板 | 需確認發票、收據／打印、送貨單的編號規則、是否需保存發出紀錄、各品牌 logo／公司資料及繁中／英文版面。 |
| 取消後財務處理 | 本 PRD 定義為 void；需確認是否需同步沖銷已收付款、庫存、工場單與派送單。未確認前不可自動做財務沖銷。 |

### 5.3 查詢與效能

1. 列表資料必須由伺服器端分頁、篩選、排序，不得先載入全部訂單再於瀏覽器過濾。
2. 查詢需避免每列逐一載入 Tag、數量、節日或待辦資料（N+1）；應以 view、RPC 或聚合查詢一次取得列表所需欄位。
3. 節日、Tag、地址／電話搜尋欄位需建立相應索引或採用已審核的全文搜尋方案。
4. 列表更新後，操作成功的單筆資料需即時刷新；不要求本期加入跨使用者即時訂閱。

## 6. 權限與稽核

| 能力 | 權限要求 |
| --- | --- |
| 查看列表、客戶資料、Tag、節日 | 訂單列表查看權限。 |
| 查看總額、未完成付款 | 財務查看權限。 |
| 編輯、複製 | 訂單新增／編輯權限。 |
| 新增／移除更多代辦狀態 | 訂單編輯／代辦更新權限。 |
| 留言 | 訂單留言權限。 |
| 取消訂單 | 獨立的訂單取消權限；不得僅因可編輯即擁有取消權。 |
| 送貨單、收據、發票 | 對應的單據查看／列印權限；若尚未有細分權限，需在開發前決定是否先沿用訂單查看權限。 |

取消、複製及單據列印（如需保存紀錄）應寫入操作稽核：操作者、時間、訂單 ID、動作、結果及失敗原因（如有）。

## 7. 驗收標準

1. 在「所有列表」可看到品牌、訂單號碼、客戶三項資料、節日、地區、送貨日期、出車與送餐時間、Tag、數量、總額、代辦及操作欄，順序符合第 4.1 節。
2. 在每個其他預設訂單列表，以上欄位與操作均存在，唯「代辦」欄不顯示。
3. 「所有列表」中，未結餘額大於 0 的訂單顯示「未完成付款」；未傳送工場的訂單顯示「未傳送到工場」；符合兩項時同時顯示。
4. 使用者可在代辦欄開啟「選擇更多狀態」彈窗，對同一訂單新增或移除改期未定、WP、BW、FP、KLOOK、Alipay、已拆單、月結等多個狀態；系統自動代辦不可於此移除，重新載入後手動狀態仍存在。
5. 送貨日期可在單日 Datepicker 與日期範圍 Datepicker Range 間切換；「今日送貨」正確顯示香港時區今日訂單，「未來30日送貨」正確顯示今天起連續 30 個曆日的訂單，且可與其他篩選條件共同套用。
6. 品牌與地區可分別多選篩選，且多選符合 OR 邏輯；節日篩選可分別得到全部、節日、非節日及指定節日的正確結果；Tag 多選符合 AND 邏輯，並可篩選更多狀態。
7. 以電話或地址文字搜尋時，能找到相符訂單；篩選後分頁與總數正確。
8. 每筆訂單皆可按權限看到編輯、溝通、取消、送貨單、打印、發票及複製操作。
9. 只有送貨狀態為「待接單」的訂單可看到並執行取消；取消必須輸入 `void` 才能確認，成功後訂單不再被當作有效訂單計入數量、總額或待辦。
10. 複製後會進入新訂單編輯頁，原單不受影響，新單沒有付款、留言、單據編號、派送／工場狀態及取消狀態。
11. 送貨單、收據／打印與發票預覽可正常顯示及列印，且內容與對應訂單一致。
12. 無財務查看權限者看不到總額、未完成付款或其他付款金額資訊。
