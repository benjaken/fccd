# FCCD Customer Portal 需求規格 v2.0

版本：v2.0｜日期：2026-10-13｜語言：繁體中文｜貨幣：HKD｜時區：Asia/Hong_Kong

本版以 2026-10-13 會議紀錄為需求基線，並納入同日確認的六項執行決定。它取代 v1.9 及更早 PRD 中互相衝突的規則。v1.8、v1.9 保留作歷史。後續開發與驗收以本版為準。本文件是目標規格，不代表功能已完成。

會議已定、不再重開：Email OTP；所有訂單每 HK$25 餐費 1 分；個人訂單積分歸個人、企業訂單積分歸企業；預備訂單沿用現有報價／訂單流程；企業權限由企業配置；VIP 訂飯需要截單、週期餐單及批量訂餐；每張訂單只可評價一次；付款憑證由 FCCD 管理員審核。

## 1 2026-10-13 確認的執行決定

| 項目 | 決定 |
|---|---|
| 舊積分 | 沒有需要遷移的舊餘額。直接按新規則入帳。 |
| 積分規則 | 預設每 HK$25 合資格餐費 1 分。FCC 可發布新版本修訂門檻；已鎖定在訂單上的版本不變。 |
| 積分使用 | 不可抵餐費、運費或應付金額。兌換對象是禮品。禮品目錄及履約另定。 |
| 入帳 | 只計餐費，運費不計。訂單完成後入帳，提交預備訂單時不入帳。不足 HK$25 的餘額捨去。門檻為 0 時暫停賺分。 |
| 取消及退款 | 取消或全額退款扣回該單已入積分。部分退款按退回餐費比例扣回。不足扣時記待處理，不做成負分抵下一張單。 |
| 預備訂單 | 與正式訂單同一筆訂單資料、同一套狀態。客戶提交後是報價階段，FCCD 沿用現有報價流程確認後才成為正式訂單。不另建 Portal 專用審批。 |
| 互動飯盒 | 使用內部產品規格，由後台設定可售產品、價格及供應。到會餐牌仍只連到品牌官網。 |
| 身份 | 同一人可同時屬於多個企業。以目前身份分隔訂單、地址及積分。不做跨企業合併帳單。 |
| 企業權限 | 先維持 Admin 與 Member，不再增加第三種固定角色。權限目錄草稿：成員管理、訂餐管理、訂單查看、訂單匯出、餐單管理、送貨資料、積分查看、積分兌換、團隊設定。欄位級再細化。企業權限不能改 FCCD 平台管理權。 |

## 2 與現有程式的差距

已對齊並應保持：Email OTP、個人／企業入口、到會官網連結、付款憑證由 FCCD 審核、訂單查詢與收據、企業邀請、地址按身份分開。

已按本版停用：結帳使用積分抵扣應付金額。新單 `p_points` 必須為 0。賺分改為 `hkd_per_point`，預設 25。

尚未改完，不能當成已符合本版：

- 企業餐牌提交仍直接寫入正式訂單，尚未進入報價階段。
- 互動飯盒尚未作為個人可訂產品從後台發布。
- 個人積分帳戶、禮品兌換、到會訂單入分尚未實作。
- 一人仍只能掛一間有效企業。
- 權限仍只有 Admin／Member，九項權限尚未可配置。
- VIP 訂飯、訂單評價、公司資訊頁仍未做。

## 3 下一項開發

先把客戶提交改成現有報價單：同一筆 `orders` 資料，提交時處於報價狀態，確認後才是正式訂單。互動飯盒的可售項目由後台從內部產品設定。在這項完成前，不要把企業餐牌下單或積分抵扣再擴充。
